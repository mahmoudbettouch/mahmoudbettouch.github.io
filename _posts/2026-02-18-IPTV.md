# IPTV

## Challenge Info
* **Name:** IPTV
* **Category:** Forensics / Misc
* **File:** `PC-ACHRAF.7z`

## Description
> This write-up documents a full forensic and reverse-engineering workflow involving a two-stage Android malware campaign.
>
>Starting from a logical Windows image, we recover a malicious APK from Chrome cache artifacts, analyze its dropper behavior, extract and reverse the second-stage native payload, and uncover credential exfiltration via the Telegram Bot API.
>
>The investigation highlights practical techniques used in real-world incidents: artifact recovery from browser cache, APK static/dynamic analysis, JNI/native obfuscation bypass, and OSINT pivoting on exposed Telegram infrastructure to trace stolen data.

---

## Solution / Write-up

### Analysis of the AD1 file
We are given an AD1 file, it's a logical image of the users directory from a windows machine. We will need FTK imager to view its content

We can mount it directly with ftk imager or import it in ftk imager:
<img src="/assets/img/posts/ideh-iptv/image1.png" />

The image file only contains the Users directory, there is only one non default user it's achraf. let's check the desktop directory first.

<img src="/assets/img/posts/ideh-iptv/image2.png" />

We have a whatsapp conversation screenshot

<img src="/assets/img/posts/ideh-iptv/image3.png" width="200" />

Achraf asked a friend for an app to watch live football, it turned out to be malware but he said he deleted it from his phone and his laptop. 
Let's check his downloads folder.

<img src="/assets/img/posts/ideh-iptv/image4.png" />

It's empty, let's check his browsing history.
Using [BrowsingHistoryView](https://www.nirsoft.net/utils/browsing_history_view.html) from Nirsoft we can open history file found in appdata folder of the user. We can find that he was searching for Yacine Tv app but no clear download link.

<img src="/assets/img/posts/ideh-iptv/image5.png" />

When using chrome, it usually stores browsing data like html, css, js, and also application data in cache. There's Nirsoft's [ChromeCacheView](https://www.nirsoft.net/utils/chrome_cache_view.html) that allow us the recover these files from the cache.

<img src="/assets/img/posts/ideh-iptv/image6.png" />

And here it is, the app we were looking for. Let's export it and analyze it.

### APK Analysis

let's start by statically analysing the apk using jadx.

<img src="/assets/img/posts/ideh-iptv/image7.png" />

There's not so much code we can analyse, it uses native code to implement the full app logic. and with a bit of googling we can find that it uses NMMP packer that relies dex virtualization rather than simple obfuscation. 

The `AndroidManifest.xml` shows an interesting permission `android.permission.REQUEST_INSTALL_PACKAGES` so that may hint us that this apk it's just a dropper, and the malware will be installed later on.

<img src="/assets/img/posts/ideh-iptv/image8.png" />

So instead of losing a lot of time trying to reverse the libraries let's run it inside an emulator. When opening it we can see a pop that ask us for permission, and after that it will install another app called `Yacine TV`.

<img src="/assets/img/posts/ideh-iptv/image9.png" />

after installing it we're granted by a login page to validate bank account, that's the second stage malware that was packed inside the first apk we analyzed

<img src="/assets/img/posts/ideh-iptv/image10.png" />

let's get its package name, and pull it with adb. First let's list all user installed packages
` adb shell pm list packages -3` 

<img src="/assets/img/posts/ideh-iptv/image11.png" />

Get the path of `com.yacine.tv` since we know the dropper is `qlshbftoz.lsxnprgdzx.lcwjh`

`adb shell pm path com.yacine.tv`
`adb pull /data/app/.../base.apk second_stage.apk`

<img src="/assets/img/posts/ideh-iptv/image12.png" />

Next we'll analyse the second stage apk in jadx. In the beginning of the MainActivity class we can see that it loads a native library and declares a native function `checkAndSendLogin()` that seems it's the exfiltration function.

<img src="/assets/img/posts/ideh-iptv/image13.png" />

The function is used after validating login and password field aren't blank.

<img src="/assets/img/posts/ideh-iptv/image14.png" />

We need to extract the `libtv.so` library into the `assets/lib` directory and open it in IDA, since it’s an ELF file. C++ native functions follow the JNI naming pattern `Java_<package>_<Class>_<method>`, so we can find our function in IDA’s Exports tab.

<img src="/assets/img/posts/ideh-iptv/image15.png" />

The decompilation shows that the exfil is done using telegram api bots, so we need to find that bot key somewhere. 

<img src="/assets/img/posts/ideh-iptv/image16.png" />

Bot token is appended to the url and is stored inside the v73 variable. First, the code reconstructs the bot token into v73 by looping over a global .rodata byte array (byte_42520) and XOR’ing each of its 46 bytes with 0x42, pushing the decoded characters into a std::string (so the token never appears as plaintext in the binary).

<img src="/assets/img/posts/ideh-iptv/image17.png" />

We can recover it using cyberchef like the following

<img src="/assets/img/posts/ideh-iptv/image18.png" />

Same thing for the chat_id, it's stored in v70 variable in ASCII.

<img src="/assets/img/posts/ideh-iptv/image19.png" />

Here's the chat_id `-5123324492` and since it starts with a "-" we know it's a group chat. We can enumerate this telegram bot using just these curl commands 

`curl -s "https://api.telegram.org/bot8262123850:AAG4PXWqAbBG8ndzrBf5_hYtXkf6I4MYMmo/getChat?chat_id=-5123324492" | jq`

<img src="/assets/img/posts/ideh-iptv/image20.png" />

### Osint pivoting to telegram

We can see usually this `getUptades` endpoint used to get the latest messages recieved by the bot, but here it leads us to nothing.

<img src="/assets/img/posts/ideh-iptv/image21.png" />

So the idea is to either get an invite link to the group chat the bot is using or use these interesting api endpoints [forwardMessage](https://core.telegram.org/bots/api#forwardmessage) or [forwardMessages](https://core.telegram.org/bots/api#forwardmessages).

<img src="/assets/img/posts/ideh-iptv/image22.png" width="600" />

They forward messages already sent in the chat to your own chat with the bot. All we need to do is initiate a conversation with the bot, retrieve our chat_id using the getUpdates API endpoint, then forward the messages that were sent in the exfiltration group chat to our chat.

<img src="/assets/img/posts/ideh-iptv/image23.png" />

Wrote a simple python script that will forward to me the first 100 messages from the chat group with chat id `-5123324492`.

<img src="/assets/img/posts/ideh-iptv/image24.png" width="450" />

And here we got our flag:

<img src="/assets/img/posts/ideh-iptv/image25.png" />
